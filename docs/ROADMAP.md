# 보완할 점과 우선순위

2026-10-15 복구 소스를 직접 확인한 결과입니다. 아래 항목은 작업을 시작할 수 있는 수준의 제안이며, 성능이나 정확도를 측정한 결과는 아닙니다.

## 1. 검색 에이전트 복구 — 최우선

원본 `AllAgent.py`가 `Agent.py`와 같은 내용이었고, `AllAgent` 클래스와 아래 메서드가 없었습니다. 이 상태에서는 `CurriculumAgent`의 상속부터 실패합니다.

공개본은 클래스를 명시적으로 만들고, 아직 구현되지 않은 기능은 복구 안내를 반환합니다. 다음 계약을 만족하는 실제 구현이 필요합니다.

| 메서드 | 필요한 역할 |
| --- | --- |
| `directagent` | 학과·교과목 조건을 추출해 직접 조회하고 응답 생성 |
| `searchagent` | 직접 조회가 실패할 때 검색 기반 응답 생성 |
| `search_db` | 커리큘럼 추천에 필요한 교과목 레코드 반환 |
| `recommend_relevant_department` | 핵심 기술과 관련된 학과 후보 반환 |
| `recommend_relevant_department_all` | 학과 후보와 검색 점수 반환 |

`search_db`가 반환하는 각 교과목에는 최소한 `교과목명`, `학과`, `수업목표`, `학년`, `학기`, `권장선수과목`이 필요합니다. 먼저 실제 원본 구현을 복구하고 반환 형태를 확인하는 것이 좋습니다.

**완료 기준:** 강의명 조회·학과 커리큘럼 조회·진로 기반 추천 각 1개 이상의 예제가 실제 데이터로 동작하고, 데이터가 없을 때 빈 결과를 일관되게 처리합니다.

## 2. 데이터와 검색 인덱스 재현성 — 최우선

ZIP에는 이름이 비슷한 DB·JSON·FAISS 파일이 여러 개 있으며, 원본 `setting.py`가 기대하는 학과 JSON 경로와 실제 ZIP 위치도 달랐습니다. DB 스키마나 인덱스 생성 스크립트가 없어 새 환경에서 동일하게 재구축하기 어렵습니다.

- 하나의 표준 교과목 스키마와 `course_id`를 정의합니다.
- 학과 소개와 강의계획의 출처, 기준 연도·학기, 수집·갱신일을 기록합니다.
- 전처리·데이터 적재·임베딩 생성·인덱스 구축을 각각 실행 가능한 스크립트로 만듭니다.
- 인덱스와 함께 임베딩 모델명·차원·정규화·거리 함수·원본 행 대응 정보를 저장합니다.
- 작은 검증용 데이터와 검색 질문 목록을 두고 관련 강의가 상위 결과에 포함되는지 확인합니다.

**완료 기준:** 새 환경에서 문서에 적힌 순서만으로 데이터를 적재하고 같은 검색 결과를 재현할 수 있습니다.

## 3. 추천 결과를 구조화하고 제약을 코드로 검증 — 높음

`CurriculumAgent.generate_curriculum`은 모델이 출력한 문자열을 줄바꿈과 괄호로 나눠 과목을 추출합니다. 출력 형식이 조금만 달라져도 과목명·학과가 잘못 해석될 수 있습니다. 프롬프트로만 지정한 “중복 금지”, “학기별 다섯 과목”, “선수과목 고려”도 실제 만족 여부가 보장되지 않습니다.

- 모델의 선택 결과를 `course_id`, `reason`, `semester` 같은 구조로 받습니다.
- 결과의 ID가 검색 후보 안에 존재하는지 코드로 검사합니다.
- 중복은 과목명 대신 식별자로 판단합니다. 같은 이름의 다른 과목과 재개설 과목도 구분합니다.
- 선수과목 관계, 개설 학기, 총 학점, 학생의 기이수 과목을 검증합니다.
- 불가능한 계획은 억지로 채우지 않고 충족하지 못한 조건을 반환합니다.
- 추천 이유와 수업목표·출처를 함께 보여 학생이 검토할 수 있도록 합니다.

원본은 상위 학년부터 역순으로 추천합니다. 결과를 학생에게 보여줄 때는 실제 이수 순서대로 정렬하고, 선수과목이 앞선 학기에 배치되는지 별도로 확인하는 편이 좋습니다.

**완료 기준:** 추천 목록에 없는 과목 생성, 중복 과목, 선수과목 순서 위반을 자동 검사하고 실패 사례를 테스트합니다.

## 4. 비동기 API 및 SDK 이관 — 높음

현재 `async` 함수 안에서 동기식 `openai.ChatCompletion.create`와 동기 스트림 순회를 사용합니다. 한 요청의 네트워크 대기가 다른 요청 처리를 막을 수 있습니다. 공개용 정리 단계에서는 원본 인터페이스 호환을 위해 SDK `0.28.1`을 고정했습니다.

현재 SDK로 이관할 때 생성·분류·스트리밍 호출을 함께 수정하고, 비동기 클라이언트, 호출 시간 제한, 재시도 횟수, 취소 처리를 명시합니다. 모델도 함께 임의로 바꾸기보다는 원래 질문 목록으로 응답과 비용을 비교한 뒤 결정하는 것이 좋습니다. [OpenAI SDK 안내](https://developers.openai.com/api/docs/libraries), [스트리밍 안내](https://developers.openai.com/api/docs/guides/streaming-responses)

**완료 기준:** 동시 질문을 보내도 각 요청의 스트리밍이 유지되고, 연결 중단·API 오류·시간 초과가 종료 처리로 이어집니다.

## 5. 질문 분류와 대화 문맥 개선 — 보통

현재 분류는 `Category:`와 `Continuation:` 텍스트에 의존하며, 원본은 진로·학과 커리큘럼 경로에서 `history=None`을 넘겼습니다. 공개본은 문맥 전달과 잘못된 분류 결과의 기본 처리를 수정했습니다.

- 분류 결과를 구조화하고 허용된 값만 받습니다.
- 사용자·모델 대화 이력을 역할별 메시지로 전달합니다.
- “그럼 3학년부터?”, “그 과목 대신 다른 과목은?” 같은 후속 질문 사례를 검증합니다.
- 분류 불확실성이 높은 경우에는 학생에게 필요한 조건을 묻도록 합니다.

**완료 기준:** 단독 질문과 후속 질문을 포함한 고정 질문 목록으로 분류와 문맥 처리를 평가합니다.

## 6. 배포 전 요청 처리 정리 — 보통

현재는 복구본의 GET + EventSource 흐름을 유지합니다. 질문과 대화 기록이 URL에 포함되므로 서버·프록시의 URL 로그에 남을 수 있고, 긴 대화는 URL 길이 제한에 걸릴 수 있습니다.

- POST 요청 본문과 스트리밍 `fetch` 방식으로 옮깁니다.
- 사용자 인증, 사용자별 요청 제한, API 사용량 제한을 도입합니다.
- 원본 개발용 서버 대신 운영용 ASGI 실행 구성을 만듭니다.
- 예외 로그에 원문 질문·개인 설정·API 키가 기록되지 않도록 검사합니다.

**완료 기준:** 질문을 URL에 노출하지 않고, 인증되지 않은 대량 요청과 오래 걸리는 요청을 통제합니다.

## 이번에 정리한 사항

- 연결 정보와 키를 환경변수로 이동하고 `.env.example` 추가
- DB 연결을 import 시점에 열던 코드 제거, 요청별 지연 연결로 변경
- 응답 생성이 끝나기 전에 DB를 닫던 흐름 수정
- SSE 텍스트·과목 배열을 JSON 이벤트로 분리
- 완료·오류 시 EventSource 연결 종료
- 고정 서버 주소 제거, 같은 서버의 상대 경로 사용
- 사용자 입력·과목 정보의 HTML 삽입 제거
- 원본 데이터·캐시·중복 UI 파일을 공개본에서 제외
- 실행 안내와 외부 API 없는 회귀 테스트 추가

원본에는 DB 비밀번호가 들어 있었습니다. 그 비밀번호를 현재도 사용하는 연결이 있다면 변경하는 것이 좋습니다. 실제 값은 공개본과 문서에 포함하지 않았습니다.
